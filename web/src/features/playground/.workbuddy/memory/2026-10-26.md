# 2026-10-26

- 全模块 bug 审查（未改代码）：通读 playground 全部 hooks/lib/components，确认的高严重性问题：
  1) use-playground-state.ts 消息加载 effect 依赖 [config.type]，切 tab 会用 localStorage 旧数据覆盖内存态；文字流式中切 tab 还会把后续 chunk 写进错误会话（updateMessages 默认 tab=config.type）。
  2) persistMessages 三个 tab 共享一个 debounce timer（messagesSaveTimerRef），tab A 的待保存会被 tab B 的更新 clearTimeout 掉，A 的消息可能永不落盘。
  3) storage-schema.ts playgroundConfigSchema 缺 type / createVideoMode 字段，zod strip 导致 saveConfig 永远存不下这两个字段；playground-input-tools.tsx 切模式还用 raw setConfig 绕过 updateConfig，双重导致模式选择不持久化。
  4) 视频 metadata 残留：playground-input.tsx handleImagesChange 清空时只清 config.image 不清 config.metadata；headAndTail 缺帧时把空 url 写进 metadata.content；payload-builder 对 metadata.content 无过滤。
  5) sendNonStreamingChat 视频/图片错误路径（catch、hasChatCompletionChoice 失败）不传 tab，错误会写到当前 tab 而非发起请求的会话。
  6) 中危：saveMessages 超配额静默失败；readStoredMessagesValue 超 1MB 直接 removeItem 全部历史；stopGeneration 停止后留下空 content 的 complete 气泡。

- 第二轮独立复核（同样未改代码），新增确认：
  1) payload-builder.ts 视频分支发 `payload.resolution`，而 types.ts 注释明确说视频复用 `size` key——契约疑点，需与后端核对，若后端读 size 则分辨率设置完全失效（payload 是 any，编译器抓不到）。
  2) api.ts pollVideoTask 用 `status === 'SUCCESS'`（大写）判断成功、`'failed'`（小写）判断失败，若后端是小写 success 会一直轮询到 24h 超时。
  3) latestMessagesRef 字符串键（text/image/video）与 persistMessages 数字键（ConversationTab 0/1/2）并存，卸载兜底遍历数字键，未 persist 过的 tab 传 undefined 进 saveMessages 抛 TypeError 被吞。
  4) use-chat-handler.ts 导入了未使用的 ConsoleIcon（死代码）；isFirstIem/isSeconfIem 拼写问题。
